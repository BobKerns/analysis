## Scene `title`: タイトル

シミュレーターで考える老後の資金計画。第3回は、ベースシナリオを作ります。

前回、アリスはデータフォルダーを作りました。そのベースシナリオは、まだ空です。今回はそこに、ふたりの口座、収入と支出、そして口座の間でお金を動かすルールを入れていきます。最後には、シナリオが実行でき、お金が行くべきところへ流れるようになります。

## Scene `contents`: ベースに入れるもの

```slide
heading = "ベースに入れるもの"
body = [
  "口座と、今それぞれにある金額",
  "ルール: 毎月の収入と支出",
  "チェーン: 足りないときのお金の出どころ",
  "カレンダー: ある日付の一度きりの変化",
]
```

ベースには、今の世帯と、今の計画を入れます。まず口座と、今それぞれにある金額。次に、毎月お金を動かすルールです。給料や社会保障の年金が入り、支出が出ていきます。それからチェーン。口座のお金が足りなくなったとき、どこから持ってくるかを決めます。最後にカレンダー。ある日付に一度だけ起きる変化を書きます。ほかのシナリオはすべてベースの上に作るので、ここをきちんと作ることが大切です。

## Scene `person`: ビルを世帯に加える

{sim init|シム・イニット}は、アリスを世帯に入れました。次はビルです。{sim person add|シム・パーソン・アド}で、アイディー、名前、生年月日、そして役割を指定します。プライマリーは、税や遺族の扱いの対象になる、ふたりの配偶者のひとりという意味です。人はすべてのシナリオで共有されるので、この変更はすべてのシナリオに及びます。

## Scene `kinds`: 4種類の口座

```slide
heading = "4種類の口座"
body = [
  "資産: 当座預金、普通預金、投資、家",
  "負債: 住宅ローン、借入",
  "収入: お金の出どころ。たとえば給料",
  "支出: お金の行き先。たとえば生活費",
]
```

シミュレーターが追いかけるものは、すべて口座で、口座には4つの種類があります。資産は、持っているもの。当座預金、普通預金、投資、家です。負債は、借りているもの。住宅ローンなどです。残りの二つは、全体の端にあたります。収入の口座はお金の出どころで、たとえばビルの給料です。支出の口座はお金の行き先で、たとえば生活費です。どの1ドルも、ある口座から別の口座へ動くので、跡を残さずに現れたり消えたりするお金はありません。

## Scene `accounts`: 口座を加える

{sim account add|シム・アカウント・アド}で口座を作ります。名前、種類、そして何の口座かを表すサブカインドを指定します。当座預金は現金の口座で、ふたりの共有、今は1万5千ドル入っています。普通預金も現金ですが、利息が付きます。シリーズは増え方の率を指定するもので、ここではベースの市場の前提にある現金の利率です。利息は通常の所得として課税されます。アリスのトラディショナル・アイアールエーは退職口座です。アリスひとりのもので、ロットのサブカインドがトラディショナル・アイアールエーであることを示すので、お金を引き出すときに課税されます。株式で運用しています。どのコマンドも、何をどこに書いたかを教えてくれます。どれもふつうのファイルなので、手で編集することもできます。

## Scene `lots`: ロットが二つある口座

口座は、実は、ロットの集まりです。たいていの口座にはロットが一つだけですが、ふたりの証券口座には、増え方の違うものが二つあります。株式のファンドと、債券のファンドです。そこで、口座は空のまま作り、それぞれの保有をロットにします。必要なものが足りないコマンドは、残りを尋ねてくれます。ここでは{sim account lot add|シム・アカウント・ロット・アド}を、何も付けずに実行します。口座、ロットの名前を尋ね、そのあとも一つずつ、上に一行の説明を付けて質問します。株式のロットは、米国株の率で増えます。この口座で最初に増えるロットなので、その増加がどう課税されるかも尋ね、キャピタルゲインを勧めてきます。今の残高は24万ドルで、買ったときに払ったのは15万ドル。これが取得価額で、売ったときの利益をシミュレーターが分かるようにします。最後にロットの内容と、同じことを1行でするコマンドを表示するので、次からはそれを使えます。債券のロットは、その1行の形で加えます。

## Scene `more-accounts`: 残りの口座

残りの口座も同じように加えます。ビルのロス・アイアールエー、ふたりそれぞれの給料と社会保障の年金の収入口座、そして生活費、医療費、連邦税の支出口座です。{sim account list|シム・アカウント・リスト}は、すべての口座を、始まりの残高と、それぞれが増える率と一緒に表示します。証券口座は二つのロットが違う率で増えるので、シリーズが二つ表示されます。キャピタルゲインや利息など、いくつかの口座は自動で作られたものです。投資の増加をそこから入れることで、正しく課税できるようにしています。

## Scene `rules`: お金を動かすのはルール

```slide
heading = "お金を動かすのはルール"
body = [
  "毎月や毎年の決まった額。インフレに合わせて増やせる",
  "受給開始年齢からの社会保障の年金",
  "最低引き出し額",
  "毎年の所得税、ほか",
]
```

口座はお金を持ち、ルールはお金を動かします。スケジュールされたルールは、決まった周期で、ある口座から別の口座へ、計算した額のお金を動かします。いちばん簡単なのは決まった額で、インフレに合わせて増やすこともできます。ほかの種類では、受給開始年齢から社会保障の年金を計算したり、アリスが年齢に達したらアイアールエーからの最低引き出し額を計算したり、住宅ローンの返済や、毎年の所得税を計算したりします。

## Scene `scheduled`: 収入と支出

{sim scheduled add|シム・スケジュールド・アド}には、開始日、お金が出る口座、入る口座、そして金額を指定します。アリスの給料は月8千ドルで、給料の口座から当座預金へ、今年の1月から入り、インフレ、つまりシーピーアイのシリーズに合わせて増えます。退職する2028年6月で終わります。パーソンは誰のルールかを示すので、もしそれより先にアリスが亡くなれば、そこでも終わります。ビルの給料も同じで、2030年12月に終わります。そして生活費は、当座預金から月7千5百ドルです。パーソンはジョイント、つまり世帯なので、ふたりのどちらかが生きている限り続きます。

## Scene `more-scheduled`: 残りのルール

残りのルールは、ダッシュダッシュ・カインドで指定する別の種類です。医療費は、もう一つの決まった額。社会保障の年金は、アリスが67歳、ビルが70歳で受給を始めます。アリスの最低引き出し額。そして連邦所得税で、毎年4月に前の年の分を精算します。{sim scheduled list|シム・スケジュールド・リスト}は、すべてのルールを表示します。上のほうのグロースという名前のルールは、自分で書いたものではありません。それぞれのロットのシリーズから作られ、毎月ロットを増やします。税については第7回で詳しく見ます。

## Scene `first-look`: まずは結果を見る

これで実行できます。{sim run|シム・ラン}は2060年まで1か月ずつ進めますが、もう警告が出ています。2032年11月に、当座預金がマイナスになりました。{sim explain|シム・エクスプレイン}で、実行結果をざっと見てみます。いちばん下に同じ警告があり、その上には毎年の純資産があります。実行は止まらず続き、計画は豊かに見えます。純資産は増え続け、2060年には5百万ドルを超えます。ところが、普通預金や投資からお金を取り出すものが何もありません。給料が止まると、支払いは当座預金から出ていき、当座預金は下がり続けるだけです。このような不足があっても実行は止まらないので、目で見て、計画を直せます。

## Scene `chains-card`: チェーン: お金の出どころ

```slide
heading = "チェーン: お金の出どころ"
body = [
  "口座とロットのリスト。順番に試す",
  "当座預金は最低残高を保ち、下回りそうならチェーンから補充",
  "普通預金、債券、株式、最後にアイアールエー",
]
```

チェーンは、お金はどこから来るのか、という問いへの答えです。口座とロットのリストで、順番に試します。必要な分を最初から取り、足りなくなったら次から取ります。アリスとビルは、当座預金に少なくとも5千ドルを残しておきたいと考えています。支払いでそれを下回りそうになったら、当座預金はチェーンから補充されます。まず普通預金、次に債券、その次に株式、そして最後がアイアールエーです。アイアールエーから出す1ドルには、どれも税がかかるからです。

## Scene `chains`: チェーンを作る

{sim chain add|シム・チェーン・アド}で、スペンディングという名前のチェーンを、普通預金から始めて作ります。ソースなので、ここからお金を引き出します。{sim chain step add|シム・チェーン・ステップ・アド}で、そのあとに債券、株式、アイアールエーを、この順番で加えます。次に、当座預金のロットに最低残高5千ドルと、補充に使うチェーンを設定します。{sim chain show|シム・チェーン・ショウ}は、チェーンを木の形で描きます。どのステップも、必要な額の残り全部を受け持ち、このチェーンが当座預金を補充します。ステップは割合で受け持ったり、ある額までで止めたりもできます。チェーンのガイドに、作り方の例があります。

## Scene `chains-graph`: チェーンを図で見る

ダッシュダッシュ・グラフを付けると、{sim chain show|シム・チェーン・ショウ}は同じチェーンを流れ図で描きます。アイターム・ツー、キティ、ブイエス・コードのターミナルなど、画像を表示できるターミナルで使えます。矢印をたどると、まず普通預金、次に債券、その次に株式、最後にアイアールエーと、当座預金が5千ドルを下回りそうになるたびに、お金が当座預金へ流れ込みます。ダッシュダッシュ・グラフ・ファイルを使うと、図をファイルに保存して、人に見せたり、計画と一緒に残したりできます。

## Scene `chains-run`: もう一度実行する

もう一度実行すると、警告は出ません。{sim explain|シム・エクスプレイン}も、マイナスの残高はなかったと言っています。2060年の純資産は前より少なくなりますが、それが正しいのです。前は、当座預金がタダでどんどんマイナスになる一方で、支払いに使うべきお金が投資されたまま増え続けていました。今は支払いが普通預金と債券から出ているので、これが本当の数字です。

## Scene `calendar-card`: カレンダー: 一度きりの変化

```slide
heading = "カレンダー: 一度きりの変化"
body = [
  "ある日付の一度きりの移動: 新しい車、贈与、相続",
  "ある日付からルールの金額が変わる",
  "ルールが止まる、率が変わる",
]
```

毎月起きることばかりではありません。カレンダーには、ある日付に一度だけ起きる変化を書きます。新しい車や贈与、相続のような、一度きりのお金の移動。ある日付から金額が変わるルール。止まるルールや、変わる率。どれも1行なので、毎月のルールはシンプルなままです。

## Scene `calendar`: カレンダーに書く

アリスとビルは、2031年6月に4万ドルで車を買い替える予定です。{sim calendar add transfer|シム・カレンダー・アド・トランスファー}で、そのお金を当座預金から生活費へ、一度だけ移します。2036年からは旅行が減ると見込んでいるので、生活費はそこから月6千5百ドルに下がります。{set-amount|セット・アマウント}は、その日付から生活費のルールの金額を変え、それより前の年はそのままにします。{sim calendar list|シム・カレンダー・リスト}は、二つの出来事を日付の順に表示します。ベースのアンサンブル用の設定は、求めない限り表示されません。それについては第6回で説明します。

## Scene `last-run`: 税引き後の計画

カレンダーを入れて、{sim networth|シム・ネットワース}で年ごとの純資産を、税引き後、今日のドルで見ます。2031年のへこみが車です。繰り延べ税は、アイアールエーと投資の利益が、使うときにまだ払うべき税で、合計から差し引かれます。これでアリスとビルのベースシナリオは、何を持っているか、何が入り、何が出ていくか、そして足りないときにお金がどこから来るかを表しています。ここから先の「もしも」は、すべてこの上に作ります。
