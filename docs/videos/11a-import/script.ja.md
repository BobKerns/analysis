## Scene `title`: タイトル

シミュレーターで考える老後の資金計画。第11a回は、データの取り込みです。

アリスとビルは、口座をもう{Quicken|クイッケン}で管理しています。証券会社のサイトからは、口座ごとの保有もダウンロードできます。同じ数字を、計画にもう一度打ち込む必要があるでしょうか。

## Scene `export`: レポートとダウンロード

```slide
heading = "二つのレポートと、二つのダウンロード"
note = "Quickenのレポート二つと、証券会社ごとのダウンロード"
```

アリスは{Quicken|クイッケン}から、レポートを二つ、{CSV|シーエスブイ}ファイルでエクスポートします。一つは純資産のレポートで、計画が始まる日のものです。すべての口座と、その残高が載っています。もう一つは、去年の取引です。それから、年の最初の営業日に、証券会社のサイトからファイルを二つダウンロードします。共同口座のポジションと、ビルのロスIRAの保有です。四つとも、ダウンロードのフォルダーに入ります。

## Scene `sources`: ファイルの形式を確かめる

{sim import sources|シム・インポート・ソーシズ}は、シミュレーターが読めるものを並べます。{Quicken|クイッケン}の二つのレポートと、二つの証券会社、{Fidelity|フィデリティ}と{Vanguard|バンガード}のダウンロードです。どれもプロファイル、つまりファイルの列を短く書いたもので、自分のものを書くこともできます。ファイルを渡すと、それぞれがどの形式かを答えます。これでアリスは、何も取り込まないうちに、四つとも読めると分かります。

## Scene `holdings`: 残高と、一度だけの質問

{sim import holdings|シム・インポート・ホールディングズ}は、純資産のレポートを読みます。どの名前も初めて見るので、一つずつ尋ね、選べるように計画の口座を並べます。{Joint Checking|ジョイント・チェッキング}は{Asset_Checking|アセット・チェッキング}。{Online Savings|オンライン・セービングズ}は{Asset_Savings|アセット・セービングズ}です。証券口座は違います。{Quicken|クイッケン}のレポートには数字が一つしかなく、計画では株と債券の二つのロットです。証券会社のダウンロードにはファンドが一つずつ載っているので、アリスはここでは{skip|スキップ}と答え、そのファイルを次に取り込みます。アリスのIRAは、計画のものと合います。ビルのロスIRAも、証券口座と同じ理由で{skip|スキップ}です。家とクレジットカードは計画にないので、これも{skip|スキップ}です。{skip|スキップ}もほかと同じ答えで、保存され、二度と尋ねられません。

アリスのIRAはファンド一つで、計画では口数で数えています。レポートには残高しかないので、取り込みはファンドの最新の価格から口数を計算し、口数を更新するかを尋ねます。配当の再投資で増えているかもしれないからです。アリスは、はいと答えます。それから、残高の前と後を示します。当座預金は1万5千ドルと入力してありましたが、レポートでは1万4,820ドルです。三つのロットが更新され、答えが保存されました。

## Scene `positions`: 証券会社のファイルを、ファンドごとに

次は、共同口座のポジションです。このファイルには、どの行がどの口座かが番号で書いてあるので、取り込みはそれが計画のどの口座かを一度だけ尋ねます。共同の証券口座です。それから、それぞれのファンドは、口座の中の同じシンボルのロットに入ります。計画の二つのロット、株と債券は、シンボルなしで入力してあったので、取り込みはファンドごとに、どこに入れるかを尋ねます。新しい名前ならロットを足し、口座にあるロットならそこに入れ、{skip|スキップ}もできます。株のインデックスファンドは株のロットに、債券ファンドは債券のロットに。マネー・マーケットでは、アリスはエンターを押し、シンボルの名前の新しいロットができます。それぞれのロットには、ファイルから残高が入り、課税口座なので取得価額も入ります。計画はマネー・マーケットのシンボルをまだ知らないので、取り込みが足し方を教えてくれます。

## Scene `roth`: この番号は、どの口座か

ビルのロスIRAは、もう一つの証券会社にあります。そのダウンロードには、中身のどこにも、どの口座かが書いてありません。ファイルの名前にだけ、口座の番号があります。そこで最初の取り込みは、その番号が計画のどの口座かを尋ね、手がかりにファイルのファンドを示します。ビルのロスIRAです。計画ではロスIRAはロット一つで、ファイルにはファンドが三つあります。ロット一つなら簡単です。ファンドごとのロットなら、それぞれが自分のファンドのように増え、計画の株と債券の割合や、アンサンブルの結果の幅に効いてきます。ビルはファンドごとのロットにしたいので、いいえと答え、エンターを押して、それぞれのロットにシンボルの名前を付けます。{--new-lots|ニュー・ロッツ}を付ければ、尋ねずにそうなります。古いロットは空になります。新しいロットが、その合計を持つからです。そして、ビルがロスIRAに入れた額、つまり元本も、お金について行き、新しいロットに残高に応じて分けられます。証券会社の取得価額はファンドを買った値段で、別のものなので、ファイルから取ることはありません。

## Scene `again`: もう一度実行する

答えは、ふつうのファイルで、取り込み元ごとのフォルダーにあります。{Quicken|クイッケン}のものは、外の口座ごとに1行で、{map|マップ}と計画の口座、または{skip|スキップ}です。共同の証券口座のものには、その番号と、ちがう名前のロットに入れたファンドごとの行があります。ロスIRAのものは、番号の1行だけです。答えを変えるには、その行を編集します。今度は{--dry-run|ドライ・ラン}を付けて、{Quicken|クイッケン}の取り込みをもう一度実行します。何が変わるかを示すだけで、何も書きません。どの名前にも答えがあるので、質問はありません。そして、変わるものもありません。計画はもう、レポートのとおりだからです。来年、新しいファイルでは、これがすべてです。取り込み元ごとに、コマンド一つです。

## Scene `sold`: 何かが変わったとき

```slide
heading = "何かが変わったとき"
body = [
  "ファンドを売った: ロットは残り、警告が出る",
  "--prune: そうしたロットを空にする(残高、口数、元本)",
  "--new-lots: 新しいファンドごとに、尋ねずにロットを足す",
  "計画の開始から1週間以上離れた日付のファイル: 警告",
]
```

来年以降のために、いくつか。ファンドを売ると、次のファイルにはもう載りません。取り込みはそのロットを残し、売ったのかもしれないと警告します。{--prune|プルーン}は、そうしたロットをすべて空にします。残高も、口数も、元本もです。{sim account lot delete|シム・アカウント・ロット・デリート}は、ロットを消してしまいます。{--new-lots|ニュー・ロッツ}は、新しいファンドごとに、尋ねずにロットを足します。そして残高は、ファイルの日付にかかわらず、計画の始めの残高として書かれます。だから計画の開始から1週間以上離れた日付のファイルには、警告が出ます。

## Scene `categories`: カテゴリーをまとめる

支出には、アリスが自分で書くファイルが一つあります。{Quicken|クイッケン}にはカテゴリーが何十もありますが、計画に要るのは少しだけです。このファイルが、それをまとめます。{Groceries|グローサリーズ}と{Restaurants|レストランツ}は{Food|フード}に。{Utilities|ユーティリティーズ}と{Home Repair|ホーム・リペア}は{Home|ホーム}に。{Shopping|ショッピング}は{Everyday|エブリデー}になります。書かなかったカテゴリーは、{Other|アザー}に入ります。

## Scene `estimates`: 見積もりをどける

第3回で、アリスとビルは見積もりを二つ入力しました。生活費が月7,500ドル、医療費が月900ドルです。取り込みはこれから、実際に使った額からルールを書きます。両方あると二重に数えられるので、先に二つの見積もりを消します。

## Scene `transactions`: 支出が支出のルールになる

{sim import transactions|シム・インポート・トランザクションズ}は、1年分を読み、カテゴリーごとに平均の月の額を出します。{--from-account|フロム・アカウント}は、お金の出どころで、当座預金です。それから、カテゴリーごとに、どの支出の口座に入れるかを尋ねます。アリスとビルの支出の口座は、生活費と医療費の二つです。{Health|ヘルス}は医療費に、残りは生活費にします。カテゴリーごとに、毎月の、インフレとともに上がるルールが一つ書かれます。{Everyday|エブリデー}は月4,300ドル、{Food|フード}は1,050ドルです。合わせて月およそ7,700ドルで、アリスとビルの見積もりは8,400ドルでした。どのルールにも、生成されたという印が付きます。だから来年の取り込みは、この六つを置き換え、手で書いたルールには触れません。

## Scene `saved`: 保存されるもの

```slide
heading = "importsフォルダー"
body = [
  "accounts.csv、取り込み元ごとに: 外の口座と、ファンドのロット",
  "categories.csv: 外のカテゴリーを、自分のものにまとめる",
  "expense_accounts.csv: カテゴリーごとの支出の口座",
  "すべてのシナリオで共有。名前の変更にもついていく",
]
```

取り込みが覚えたことは、すべて一つのフォルダーにあります。シナリオのフォルダーの隣の、{imports|インポーツ}で、中に取り込み元ごとのフォルダーがあります。すべてのシナリオが共有するので、もしものシナリオで、また尋ねられることはありません。計画の口座の名前を変えると、保存された答えもついていきます。そして、答えにある口座がそのシナリオにないときは、そのシナリオのためだけに尋ね、ほかのシナリオのための答えは残します。

## Scene `others`: ほかの取り込み元

