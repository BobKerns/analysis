## Scene `how`: 税金の計算

```slide
heading = "税金の計算"
body = [

```

税金は年に1回、その年に記録されたすべてから計算し、実際と同じく翌年の4月に払います。通常所得は、給与、伝統的IRAからの引き出し、利息です。長期の譲渡益はその上に積み、もっと低い専用の税率をかけます。社会保障年金は、ほかの所得しだいで一部が課税されます。そこから控除を引きます。標準控除と項目別控除の、大きいほうです。申告区分は世帯に合わせて変わり、配偶者が亡くなると、残った人は単身で申告します。

## Scene `report`: その年の税金

{sim report tax|シム・レポート・タックス}は、毎年の税金を見せます。調整後総所得、控除、残った課税所得、そして税金。どれも今のドルです。2人とも働いているあいだは、年に約2万3千ドル。アリスが引退すると、9千ドルに下がります。そして2031年から2034年は、ゼロ。2人とも引退していて、ビルの社会保障年金はまだ始まらず、アリスの最低引き出しは2037年まで始まりません。わずかな所得は、標準控除より少ないのです。2035年から、税金が戻ってきます。

{--chart|ダッシュダッシュ・チャート}を付けると、同じ年を描きます。税金を棒で、実効税率を線で。

## Scene `after-tax`: 税引き後の純資産

税金は、純資産の意味も変えます。アリスの伝統的IRAにある50万ドルは、全部が2人のものではありません。いつ引き出しても、税金がかかります。そこで{sim networth|シム・ネットワース}は、それを差し引きます。{deferred_tax|デファード・タックス}は、IRAと証券口座の含み益を10年かけて引き出したらかかる税金。{unpaid_tax|アンペイド・タックス}は、4月に払うその年の税金です。残りが税引き後で、これが標準です。違う種類の口座にお金を置く計画どうしを、公平に比べられるからです。{--pre-tax|ダッシュダッシュ・プリタックス}で、もう一方の見方になります。

## Scene `gap`: 税金のない年

```slide
heading = "税金のない年"
body = [
  "2031年から2034年: 税金ゼロ",
  "10%と12%の税率区分が使われずに残る",
  "のちに、RMDと社会保障年金が所得を押し上げる",
  "今のうちにIRAの一部をロスへ転換: 税率は12%",
  "ロスは非課税で増え、RMDもない",
]
```

この税金のない年は、チャンスです。控除といちばん低い税率区分が、使われずに残っています。そしてのちには、最低引き出しと社会保障年金が、所得を高い区分へ押し上げます。だから安い今のうちに、IRAの一部をロスIRAへ移します。移した額はその年の所得として、10か12パーセントで課税されます。そのあとは非課税で増え、非課税で引き出せ、最低引き出しもありません。

## Scene `convert`: ロス転換

新しいシナリオ{convert|コンバート}を、ベースの上に作ります。転換先が要るので、アリスのロスIRAを空で作ります。

それから転換そのもの、{fill_bracket|フィル・ブラケット}のルールです。2031年から2036年まで毎年12月に、伝統的IRAからロスへ、その年の課税所得を12パーセントの区分の上限まで満たすだけの額を移します。その年にほかに何があっても、です。額を計算する必要はありません。

そしてロスを支出のチェーンの最後に加えます。ほかが少なくなったときに使えるように。そうしないと、手つかずのまま残ってしまいます。そして実行します。

## Scene `convert-results`: 代わりに払うものと、得るもの

{sim compare|シム・コンペア}に{--section tax|ダッシュダッシュ・セクション・タックス}を付けると、2つを年ごとに比べます。転換する年には、{convert|コンバート}はベースが払わない税金を1万から1万7千ドル払います。最低引き出しが始まるはずだった2037年からは、毎年4千から6千ドル少なくなり、それが一生続きます。全体では、今のドルで約6万ドル税金が少なくなります。

そして税引き後の純資産。{convert|コンバート}が前に出て、差は広がり続けます。2050年にはベースより7万ドル、2060年には15万ドル多くなります。一部は税金が少ないから、一部はロスにまだ払っていない税金がないからです。

## Scene `irmaa`: メディケアの上乗せ

```slide
heading = "メディケアの上乗せ: IRMAA"
body = [
  "所得が高いと、メディケアの保険料が上がる",
  "決めるのは2年前の所得",
  "区分ではなく崖: 1ドル超えると段階の全額",
  "メディケアに入っている人ごとに",
  "段階は用意済みで、インフレに合わせて上がる",
]
```

なぜ12パーセントで止めるのでしょう。理由の1つがメディケアです。加入すると、所得が高いほど保険料が上がります。所得に応じた月額調整額、IRMAAです。決めるのは2年前の所得で、税率区分のようではなく崖のように働きます。段階を1ドルでも超えると、その段階の上乗せを丸ごと、メディケアに入っている人ごとに払います。段階はシミュレーターが用意していて、インフレに合わせて上がります。

## Scene `irmaa-demo`: もっと転換する

{convert-22|コンバート・ニジュウニ}は{convert|コンバート}の上に作り、代わりに22パーセントの区分を満たします。2つの{irmaa|アーマ}ルールが上乗せをかけます。それぞれ、本人がメディケアに入った月から、当座預金から払います。

レポートには、メディケアが見る所得と、それが2年後の保険料に決めるIRMAAの段階が出ます。ここまで転換すると、2031年と2032年に第1段階を、2033年に第2段階を超えます。

{fill_bracket|フィル・ブラケット}のルールは、段階の下にとどまれます。{irmaa_tier|アーマ・ティア}ゼロは、区分にまだ余裕があっても、第1段階の手前で止める、という意味です。これで毎年が段階ゼロにとどまり、転換は4年でなく5年に分かれます。

もっと転換するほうがいいのでしょうか。ここでは、いいえ。22パーセントの区分を満たしきると、12パーセントの案より約7万5千ドル少なく終わります。第1段階の下にとどまると、その差は半分の約4万ドルになりますが、それでも少ないままです。今余分に払う税金で、のちに減る税金ほどは買えないのです。転換が得になるのは、あとで引き出すより低い税率で課税されるときです。

## Scene `medical`: 医療費の多い年

最後に、違う種類の年です。2028年にアリスが手術を受け、5万ドルが保険でまかなえなかったとします。{medical|メディカル}は新しいシナリオで、その支払いを1回きりの振替として入れます。

医療費は、項目別控除なら、所得の7.5パーセントを超えた分が控除できます。{sim deduction add|シム・デダクション・アッド}で、2028年の項目別控除を入れます。控除できるものを並べます。基準を超えた医療費、州と地方の税金、そして寄付です。シミュレーターはそれを合計し、標準控除より大きいときだけ、それも2028年だけ使います。

レポートに表れています。2028年の控除は3万ドルから4万8千ドルに上がり、税金は約3千ドル下がります。前後の年は変わりません。

## Scene `nb-tax`: ノートブック

ノートブックも同じものを見せます。純資産のノートブックの税金の節は、毎年の税金を積み上げ、右に実効税率を描きます。シナリオ比較のノートブックの税金の節は、各実行の税金を描き、その下にベースとの差を描きます。{convert|コンバート}と{convert-22|コンバート・ニジュウニ}は、はじめに多く払い、そのあと何十年も少なく払います。グラフの下の表は、合計と、各実行の税引き後の最終的な純資産です。
