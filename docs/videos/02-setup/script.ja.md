## Scene `title`: タイトル

シミュレーターで考える老後の資金計画。第2回、セットアップとインストールです。

この回では、アリスが自分のコンピューターでシミュレーターを動かせるようにして、家計のデータを入れるフォルダーを作ります。最後には、プランを実行できるようになり、どの実行もあとで正確に再現できるようになります。

## Scene `install`: 1行でインストール

インストールは1行で済みます。マック、リナックス、またはウィンドウズのダブリューエスエルでターミナルを開き、セットアップガイドにあるこの1行を貼り付けます。インストーラーをダウンロードして実行します。ギットの知識も、コードの管理方法の知識もいりません。ウィンドウズでは、先にダブリューエスエルを準備してください。その短い動画へのリンクは、セットアップガイドへのリンクと一緒に、説明欄にあります。

## Scene `what-install-does`: インストーラーがすること

```slide
heading = "インストーラーがすること"
body = [
  "ギット (git) がなければ入れる",
  "コードを retirement/analysis に置く",
  "パイソンと、コードに必要なものをすべて準備する",
  "データフォルダーを retirement/data に作る",
]
```

インストーラーは、最初に二つ質問します。コードをどこに置くか、データをどこに置くかです。たいていの人は、ホームフォルダーの中の retirement フォルダーという提案のままで大丈夫です。次に、ギットがなければインストールします。マックでは、アップルのコマンドラインツールです。開いたウィンドウでインストールを終えてから、同じ1行をもう一度貼り付けてください。そしてコードをダウンロードし、パイソンと、コードに必要なものをすべて準備します。初回は数分かかります。最後に、あなたが誰かを尋ねて、データフォルダーを作ります。あとで更新するときも、同じ1行をもう一度貼り付けるだけです。

## Scene `terminals`: 画像を表示できるターミナル

```slide
heading = "画像を表示できるターミナル"
body = [
  "マック: iTerm2 または Ghostty",
  "リナックス: kitty、Ghostty または WezTerm",
  "どこでも: VS Code のターミナル",
  "それ以外では、グラフを画像ファイルに保存",
]
```

シミュレーターは、どのターミナルでも動きます。ただ、いくつかのコマンドはターミナルの中にグラフを描けるので、そのためには画像を表示できるターミナルが向いています。マックなら、アイターム・ツーかゴースティー。リナックスなら、キティ、ゴースティー、またはウェズターム。どこでも使えるのは、ブイエスコードの内蔵ターミナルで、設定で画像表示をオンにします。それ以外のターミナルでは、グラフは画像ファイルに保存され、コマンドがその場所を教えてくれます。一覧はセットアップガイドにあります。

## Scene `two-folders`: 二つのフォルダーと、その理由

```slide
heading = "二つのフォルダー: コードと、あなたのデータ"
body = [
  "retirement/analysis: シミュレーター本体。更新してもデータには触れません。",
  "retirement/data: あなたの家計。履歴つきのテキストファイルです。",
]
```

こうして、フォルダーが二つできます。一つはコード、つまりシミュレーターそのものです。もう一つはデータ、あなたの家計、口座、プランです。この二つは、わざと分けてあります。コードを更新しても数字には触れませんし、数字があなたのコンピューターの外に出ることもありません。それぞれのフォルダーが自分の履歴を持つので、どの実行も、どのバージョンのデータとコードから生まれたのかを正確に記録できます。

## Scene `init`: データフォルダーを作る

インストーラーは、{sim init|シム・イニット}というコマンドでデータフォルダーを作ります。自分で実行することもできます。たとえば、試し用に二つ目のフォルダーを作るときです。まず、あなたが誰かを尋ねます。データの中であなたを表す、一語のアイディー。名前。生年月日は、メディケアや最低引き出し額などに関わる年齢を決めます。性別は、寿命をばらつかせたいときに生命表を選ぶためのもので、空欄でもかまいません。そして世帯の税の申告区分で、夫婦合算申告が既定です。それからコードに付いているテンプレートからフォルダーを作り、最初のシナリオ、ベースが読み込めることを確かめ、すべての最初のバージョンを保存します。

## Scene `inside`: 中身

中身はテキストファイルで、ほとんどはどの表計算ソフトでも開ける表です。{persons|パーソンズ}には世帯の人が入ります。{scenarios|シナリオズ}にはプランが入り、最初はベースです。ベースには家計そのもの、つまり口座、収入、支出、そしてお金を動かすルールを書きます。今はまだほとんど空で、次の回で埋めていきます。税の表などの標準的な前提は、ここにはコピーされません。コードから読み込まれるので、コードを更新すれば最新のままです。

## Scene `activate`: データを有効にする

新しいターミナルウィンドウを開くたびに、この1行でデータを有効にします。{sim|シム}コマンドにデータの場所を教え、プロンプトにそれを表示します。データ、あなた、そして現在のシナリオ、ベースです。ほとんどのコマンドは、別のシナリオを指定しない限り、現在のシナリオに対して働きます。{sim switch|シム・スイッチ}は、どれが現在のシナリオかを教えてくれます。

## Scene `plan`: 自分のプラン

新しいシナリオは、別のシナリオの上に作ります。{sim scenario create|シム・シナリオ・クリエイト}で、ベースの上に{my plan|マイ・プラン}を作り、それを現在のシナリオにします。プロンプトもそれに合わせて変わります。まだ自分の中身がないので、今はベースと同じです。{sim switch|シム・スイッチ}にシナリオの名前を付けると、現在のシナリオを元に戻せます。ほかのコマンドでシナリオの名前を指定しても同じです。

## Scene `notebooks`: ノートブック

```slide
heading = "ノートブック"
body = [
  "有効にしたターミナルで: analysis jupyter",
  "または VS Code でコードのフォルダーを開く",
  "グラフと表。コードを書く必要はありません",
]
```

ターミナルのほかに、コードにはジュピターノートブックが付いています。メニューやスライダーで見ていく、グラフと表のページで、コードを書く必要はありません。開くには、有効にしたターミナルで{analysis jupyter|アナリシス・ジュピター}と入力します。ウェブブラウザーにジュピターラボが開き、左側にノートブックが並びます。ブイエスコードを使っているなら、コードのフォルダーを開いて、ノートブックフォルダーから開くこともできます。第4回で一つずつ紹介します。

## Scene `commit`: 作業を保存する

コマンドでもファイルの編集でも、データを変えると、その変更はまだどこにも記録されていません。そうした変更があるままシナリオを実行すると、{sim run|シム・ラン}は変更を一覧にして、先にバージョンを保存するか尋ねます。既定のはいを選ぶと、何が変わったかを書いたメッセージを付けて保存し、それから実行します。これで実行を再現できるようになります。実行は、読み込んだ保存済みのバージョンを記録するので、あなたも、共有した相手も、あとで同じ答えを得られますし、二つの実行の間で何が変わったかも分かります。インストーラーがバックグラウンドビルドをオンにしていれば、変更を保存すると、影響を受けるシナリオがすべて裏で実行し直されます。実行せずに保存だけしたいときは、{sim commit|シム・コミット}を使います。
