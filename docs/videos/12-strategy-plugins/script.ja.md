## Scene `recap`: 割合ではなく、旅行ごとに

```slide
heading = "旅行は、行くか、1年待つか"

```

第10回の後編では、ガードレールが毎年1月に、その年の旅行にいくら使えるかを決め、全体を同じ割合で減らしました。10パーセント減らすと、7,000ドルの旅行が6,300ドルになります。アリスとビルの旅行の仕方は、そうではありません。旅行は、行くか、1年待つかです。それをする組み込みのストラテジーはないので、自分たちで書きます。

## Scene `trips`: 3つの旅行

新しいシナリオ{trips|トリップス}は、前編の{travel|トラベル}の上に作ります。月1,000ドルの旅行を、3つの旅行に分けます。{travel|トラベル}のルールは受け継いだものなので、ここで削除すると、{trips|トリップス}が始まる前に終わります。それから旅行を、それぞれ年に1回、インフレに合わせて増やして加えます。毎年6月に海外へ7,000ドル、3月に海辺へ3,000ドル、11月に家族を訪ねて2,000ドル。前と同じ、年に1万2千ドルです。どれにも、前の旅行と同じ2つの印を付けます。レポートのための{category:travel|カテゴリー・トラベル}と、ストラテジーが受け持つための{flex:optional|フレックス・オプショナル}です。

## Scene `where`: プラグインの置き場所

```slide
heading = "プラグインは、データのリポジトリのファイル"
note = "strategies/whole_trips.py: どのシナリオでも使え、データと一緒に管理され、実行ごとに写される"
```

ストラテジーのプラグインは、データのリポジトリの{strategies|ストラテジーズ}フォルダーに置くPythonのファイルです。{allocations.csv|アロケーションズ・ドット・シー・エス・ブイ}の隣です。どのシナリオでも使えます。ほかのデータと一緒にバージョン管理されるので、書き換えると、影響する実行がやり直されます。そして実行ごとに、判断したコードの写しが残るので、何が判断したのかが、いつでも正確にわかります。アリスとビルのファイルは{whole_trips.py|ホール・トリップス・ドット・パイ}です。

## Scene `class`: クラスとパラメーター

```slide
heading = "ガードレールの上に作る"
```

まず、組み込みの{Guardrail|ガードレール}を読み込み、その上に作ります。{WholeTrips|ホール・トリップス}は、手を加えたガードレールです。{register|レジスター}の行で、ストラテジーの種類になります。説明の文は、種類の一覧に表示されます。種類の名前{whole_trips|ホール・アンダースコア・トリップス}は、ストラテジーのファイルが使う名前です。自分の名前が必要なので、組み込みが知らないうちに置き換わることはありません。パラメーターは、ガードレールのものに1つ加えたものです。行きたい順に並べた旅行です。

## Scene `year-start`: 毎年1月に

```slide
heading = "毎年1月に: どの旅行が入るか"
```

毎年1月、{year_start|イヤー・スタート}は、まずガードレールに聞きます。{super|スーパー}の{year_start|イヤー・スタート}がガードレール自身の判断をして、計画の何割を使えるかを記憶に残します。その年の予算のその割合が、旅行に使える額です。{rule_budgets|ルール・バジェッツ}は、今年のそれぞれの旅行の費用を返します。そして、行きたい順に、すでに残した旅行と合わせてまだ入る旅行を残し、入らないものは見送ります。残した一覧は、その年のあいだ記憶に置き、1月のメモには、何を見送ったかを書きます。

## Scene `scale`: 旅行ごとに

```slide
heading = "旅行ごとに: 払うか、見送るか"
note = "委ねることもできる: self.delegate(Guardrail) は、ガードレールになるのではなく、持つ"
```

そして、旅行を払うたびに、{scale|スケール}が決めます。残した旅行は計画どおりに払い、見送った旅行は今年は何も使いません。その下の{in_order|イン・オーダー}は、旅行を{order|オーダー}のパラメーターの順に並べ、そこにないものは最後にします。ストラテジーは、これで全部です。組み込みの上に作る方法は、継承だけではありません。ガードレールを持っておき、1月の判断をそれに任せることもできます。ユーザーガイドに両方の書き方があります。

## Scene `rules`: ストラテジーにできること

```slide
heading = "ストラテジーに見えるもの、できること"
body = [
  "今月までの実行を読む: 残高、予算、自分の記憶",
  "未来は見えない: 計画の終わりは知っても、来年の市場は知らない",
  "答えるだけ。お金を動かすのはシミュレーター",
  "同じ入力には同じ答え: 時計、ファイル、ネットワーク、偶然は使わない",
]
```

ストラテジーに見えるのは、今月までの実行です。残高、ルールの予算、そして自分の記憶。計画がいつ終わるかは知っていますが、来年の市場がどうなるかは知りません。お金を自分で動かすことはなく、答えるだけで、頼んだことはシミュレーターが記帳します。そして、いつも同じ答えを返さなければなりません。時計もファイルもネットワークも偶然も使いません。そうでないと、同じ計画の2回の実行が食い違うかもしれません。

## Scene `check`: 確かめる

{sim strategy kinds|シム・ストラテジー・カインズ}は、組み込みと並べて{whole_trips|ホール・トリップス}を示します。説明の文と、ガードレールのパラメーターとその既定値、そして自分の{order|オーダー}です。新しいシナリオ{trips-whole|トリップス・ホール}で、{spend|スペンド}という名前のストラテジーがそれを使い、{flex:optional|フレックス・オプショナル}の印のルールを受け持ちます。パラメーターの名前を打ち間違えると、すぐに断られ、受け付けるパラメーターが示されます。正しく書けば、加わります。それから{sim strategy check|シム・ストラテジー・チェック}が、新しいPythonでシナリオを2回実行し、すべての判断を比べます。608の判断が、2回とも同じです。

## Scene `use`: 使う

ここからは、ほかのストラテジーと同じです。{sim run|シム・ラン}が新しいファイルをコミットしてシナリオを実行し、{sim strategy log|シム・ストラテジー・ログ}が毎年1月の判断を示します。この未来では、2029年にガードレールが支出を10パーセント増やします。旅行の10分の1は取れないので、{whole_trips|ホール・トリップス}は3つとも残し、計画どおりに使います。増額は何も足さず、変わるのは削減のときだけです。

## Scene `futures`: 80の未来で

第10回の後編と同じように、80の未来で試します。{sim ensemble spending|シム・アンサンブル・スペンディング}が広がりを示します。計画は、今日のドルで年に約10万ドル。最悪の5パーセントの年には、約9万ドルを使います。半分の未来で、どこかで少なくとも1度は旅行を見送り、平均すると10年に約3年です。そして中央値は計画どおり、99.7パーセントです。

## Scene `compare`: 組み込みと比べる

{sim ensemble compare|シム・アンサンブル・コンペア}は、同じように作った、そのままの旅行と、それを組み込みのガードレールで減らしたものと並べます。2060年、最悪の5パーセントの未来は、そのままでは約20万ドルの赤字、ガードレールでは3万ドルの赤字で終わります。{whole_trips|ホール・トリップス}なら、3万8千ドルのプラスです。そして上のほうでは、{whole_trips|ホール・トリップス}は何も失いませんが、ガードレールの増額は、95パーセンタイルで200万ドルを使います。その差の一部は、旅行を丸ごと見送るからではなく、計画より多くは使わないからです。

## Scene `lumpy`: 1つの未来を詳しく

アンサンブルの2番目の未来が、その代わりに払うものを示します。2036年、ガードレールは10パーセント減らし、計画の94パーセントになります。6パーセント足りないので、海外旅行は入らず、見送られます。その年の旅行の半分以上です。そして計画が足りないあいだは、見送られたままです。2058年には、2パーセント足りないだけで、また見送られます。

## Scene `tradeoff`: 引き換えにするもの

```slide
heading = "旅行を丸ごと: 引き換えにするもの"
body = [
  "最悪の未来で多く残り、上のほうで失うものはない",
  "でも、小さな削減で旅行が1つ消えることがある",
  "試してみる案: 大きな旅行を見送る前に、少しの余裕を",
  "自分たちのコードだから、変えられる",
]
```

旅行を丸ごと見送るやり方は、減らすやり方より、最悪の未来で多くを残し、上のほうで失うものはありません。でも、小さな削減で、旅行が1つ消えることがあります。それが急すぎるなら、少しの余裕を持たせる案があります。超えるのが、たとえば10パーセント未満なら旅行に行く。パラメーターを1つと、2行です。最初に試す変更にちょうどいいでしょう。自分たちのコードなので、変えられます。

## Scene `nb`: アンサンブルのノートブック

アンサンブルのノートブックは、組み込みと同じように、プラグインの結果も描きます。年ごとの支出の広がりを、点線の計画と並べて。{whole_trips|ホール・トリップス}では、上のほうはそのままの計画と同じで、下のほうは旅行1つずつ、段になって下がります。
